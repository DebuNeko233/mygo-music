# MyGo 界面开发规则

本文适用于原生 `github.com/egoist/mygo/ui` 视图。业务边界见[架构](architecture.md)，状态与后台工作见[生命周期](data-lifecycle.md)。需要修改 MyGo API 或框架版本时，同时阅读[依赖管理](dependencies-and-upstream.md)。

## 核对固定版本

```sh
go list -m -f '{{.Dir}}' github.com/egoist/mygo
```

返回的是当前实际使用的模块目录，包含 replace 后的 fork。阅读该目录的 `ui/doc.go` 和所用 API 的实现注释。不要按官方最新网页、旧经验或相似控件名称猜接口。框架迁移文档指的是模块内的 `docs/ui/migration.md`，不是本仓库同名文件。

## 构建期与持久对象

| 对象 | 可以保存的位置 | 约束 |
| --- | --- | --- |
| `ui.Element`、parts | 当前构建局部变量 | 下一次构建前失效，包括同帧再次构建 |
| `ui.Handle` | 视图 State | 跨帧查找、焦点与已提交几何 |
| `ui.Context` | 当前窗口的 UI 构建调用链 | 不放入业务状态，不交给后台任务 |
| `c.Services()` | 需要持续使用平台服务的回调 | 捕获它代替长时间捕获 Context |
| 滚动、动画、布局缓存 | 对应窗口/视图的 State | 明确覆盖、重置和释放条件 |
| 业务数据 | 共享模型或 ViewModel | 视图借用，不另造可变副本 |

不同窗口分别维护控件状态，不能把同一个焦点、滚动或动画实例当作全局业务状态。过期 Element 引起 panic 时修正所有权，不用 Valid 检查或 recover 掩盖长期保存错误。

## 身份、列表和焦点

会增删、重排或条件出现的控件必须使用稳定 `c.Key(...)`。键表达逻辑身份，不使用当前可变索引代替歌曲身份；重复歌曲需要 occurrence 等稳定区分，参考 [tracklist/keys.go](../internal/desktop/view/tracklist/keys.go)。

容器 Key 在构建子元素前设置；List 配置在 Rows 前设置。虚拟列表使用已有 ItemKey/行机制，不能为了定位某条记录构建全部前置行。

跨帧焦点和输入几何通过持久 Handle。输入回调优先使用 `handle.Bounds(c)` 读取已提交几何；`c.Resolve(handle)` 只返回当次构建值，不能捕获后延迟使用。

使用 FocusBind 表达业务侧希望打开的焦点目标，值必须可比较且稳定，零值表示没有目标。隐藏与重现时检查键盘、焦点、菜单和对话框关闭后的行为。

## 输入提交与派生值

绑定值在输入处理阶段变化，Changed/Submitted 通知会在随后构建中观察。持久字段可以直接绑定；每帧重新计算的局部值应在 OnClick/OnChange 等适合该控件的动作中写回，具体时序以固定版本 API 为准。

[侧栏开关](../internal/desktop/view/settings/sidebar.go)保存“隐藏”，界面展示“显示”，因此用局部反值，再在 OnClick 中写回：

```go
visible := !*hidden
ui.Switch(c.Key(key), &visible).Label(label).OnClick(func() {
    *hidden = !visible
    changed()
})
```

这里 hidden 指向持久配置，key 和 label 属于当前项。若只等下一帧 Changed 再读取重建的局部 visible，就可能丢失输入。涉及集合变更时采用框架提供的事件后动作，避免一边迭代一边改变同一集合。

快捷键先确定作用域：根播放命令、窗口命令和局部控件命令不能互相抢占。Handle 上绑定的命令只应在对应控件存在且可用时执行；打开正在播放或菜单后复测 Space、返回和标签切换。

## 副作用和重绘

- 渲染可以因输入或布局在一帧内重复多次。禁止无保护地写文件、请求网络、创建窗口、注册快捷键或开始下载。
- 功能命令和显式幂等加载负责副作用；设置搜索只枚举描述，不能调用控件或 I/O。
- `Invalidate` 只请求重绘，不负责同步状态。后台发布必须回到拥有状态的线程。
- `Window.Update`/App Post 是异步分发，不能假定调用结束时状态已经发布。
- 自定义绘制回调只绘制，不修改业务状态或控制后台工作。

采用稳定控件结构和 retained 状态，避免在每次字体高亮、频谱刷新时重建整页。停止、暂停、不可见和内容未变化时，应停止不必要帧请求。使用一次跟随帧读取新布局可以，但不能变成永久轮询。

## 绘制缓存与资源

`Canvas.DrawCached` 是当前 fork 的接口，用于输入未变时重用图层像素；绘制回调仍会运行，动画仍需正确请求帧。不能以“有缓存”为由停止真实动画，也不能把它直接替换成官方 Draw 并宣称性能不变。

画布、图片与纹理明确归属视图或 artwork 缓存。快速切歌、缩放、关闭和取消时释放废弃资源；普通歌词不需要模糊时不应继续持有大画布。封面切换应等最新图片就绪并保留可见旧图，避免闪出背景。

## 视觉与可访问性

复用 [components](../internal/desktop/view/components) 的按钮、图标、主题、封面和格式化。匹配已有尺寸、圆角、间距、悬停与按压反馈，不为局部功能创建另一套设计常量。

图标按钮必须有明确可访问性标签，文本按钮避免只靠颜色表达状态。操作不可用时提供可理解的禁用或错误反馈。长文本、中文/日文/英文混排、未知时长、缺少封面和空列表必须有可读表现。

重复说明集中在一处。例如侧边栏设置顶部统一说明用途，每行只留页面名和开关。用户界面不暴露内部包名、代次、测试模式等实现细节。

## 平台与验证

透明窗口、刘海、菜单栏、字体和系统快捷键能力应在所属平台文件中适配，不让普通功能 ViewModel 识别 GOOS。其他平台保留合理回退。

每个 UI 改动至少检查实际交互和对应状态。布局变化按[测试手册](testing.md)输出并查看明暗、常规与最小窗口截图；涉及高 DPI、系统窗口或 GPU 时补原生检查。不要为可逆的小样式调整编写逐字或全图匹配测试。
