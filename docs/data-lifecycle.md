# 数据、异步任务与资源生命周期

本章规定请求、账号、缓存、后台写入及原生资源的共同约束。各功能的细节见[功能索引](features/README.md)，界面对象寿命见[UI 规则](ui-development.md)。

## 1. 单一状态所有者

功能命令和已发布状态由同一所属线程管理，桌面应用通常是 UI 线程。服务内部可以用 mutex 管理 I/O 与资源，但不借此允许工作线程直接修改 ViewModel 或视图。

后台任务只捕获完成操作必需的输入，例如 ID、查询参数、scope、请求号、不可变快照及服务接口。避免捕获整个 App、视图、Context、活动切片或会变化的配置对象。

集合发布后对借用者保持只读。编辑通过新切片/新值发布；后台编码必须拿到独立快照。复制 struct 不代表其 slice/map 底层数据已复制，必须检查引用字段。

## 2. 一次请求的完整状态

开始前明确：去重键是什么、谁取消、何时允许重试、旧结果如何丢弃、错误归谁展示、成功后哪一层请求重绘。

```text
用户命令
  → 捕获作用域并生成请求身份
  → 标记 loading / pending
  → 后台 I/O
  → 投递到所属线程
  → 校验账号、请求及所有者仍有效
  → 发布成功/失败/取消状态
  → 通知重绘或下一个任务
```

以下是流程示意，不是要求每个功能复制同一个框架：

```go
request := beginRequest()
input := captureInput()
go func() {
    result, err := fetch(input)
    post(func() {
        if !isCurrent(request) {
            releaseDiscarded(result)
            return
        }
        publish(result, err)
    })
}()
```

实际实现必须同时考虑投递本身被拒绝的情况。带资源的结果使用现有 `postResource` 或等价的显式移交/丢弃释放路径，不能只在被执行的回调里释放。

## 3. 身份不只是 ID

| 身份 | 解决的问题 |
| --- | --- |
| 账号会话代次 | 同一个 UID 退出后重新登录，旧请求仍必须失效 |
| 功能请求号或对象身份 | A→B→A 后，第一个 A 不能覆盖新的 A |
| 歌曲与队列修订 | 已切歌或编辑队列时，旧预取/补全不能重启错误内容 |
| 磁盘缓存 epoch | 清理、切目录后，旧请求不能重新写回已清除内容 |
| 窗口/注册代次 | 关闭窗口或重新注册快捷键后，旧系统回调不能改变新状态 |

取消 context 可以停止 I/O，但无法保证回调尚未入队，因此取消和结果有效性检查通常都需要。过期结果不应清除新请求的 Loading，不应覆盖新的 Error，不应触发播放或持久化。

关键实例：[账号模型](../internal/viewmodel/account/account.go)、[全局快捷键](../internal/app/hotkeys.go)、[App 分发器](../internal/app/dispatch.go)。

## 4. 缓存与网络的竞合

- 缓存先到可以提供离线内容，网络成功后应发布最新结果。
- 缓存读取晚到时不能覆盖已经接受的网络结果。
- 请求失败可保留已显示数据，Loading/Error 与数据是否存在分别表达。
- 成功的空结果与失败不同；成功返回空集合可以替换旧内容，失败不能伪装成空集合。
- 去重后的可见行数不一定等于服务端原始游标，分页不能按去重长度错误推进。
- 刷新若使用暂存新列表，必须在策略规定的完整时点统一发布，期间旧列表继续可用。

网盘整表刷新、首页模块独立发布和最近播放分类并行各有不同策略，不能统一成“任一失败清空全部”。

## 5. 重试与离线

网络连通性只是系统路由状态，不证明网易云请求成功。掉线通知取消旧连接上的请求和 body 读取；重连使用新 context。临时故障、风控、明确不可播和永久错误应按已有分类处理。

自动恢复只针对需要恢复的可见数据或播放任务，使用退避且避免重复请求。健康空闲页面不得为检查恢复持续请求动画帧。手动重试可以覆盖部分自动重试不处理的错误，但仍需要有效性和权限检查。

歌词请求失败不等于纯音乐，音频解码失败不等于正常播完，缺少钥匙串不等于未登录或没有凭据项。修改错误分类时检查所有使用该分类的 UI 和恢复流程。

## 6. 持久化的事实与责任

| 数据 | 当前入口 | 契约 |
| --- | --- | --- |
| 用户设置 `settings.json` | [preferences/settings.go](../internal/preferences/settings.go) | 加载先取默认值；无效 JSON 整体拒绝；Path 不从 JSON 接受 |
| 播放快照 `session.json` 与进度旁文件 | [sessionstore/store.go](../internal/sessionstore/store.go) | token 匹配才用进度覆盖快照；旧格式保持可读 |
| 本地曲库 `local-music.json` | [localcatalog](../internal/localcatalog) | 稳定本地身份；成功写入后再发布编辑 |
| 账号凭据 | [netease/auth.go](../internal/netease/auth.go) | 系统凭据存储；错误分类和保存失败可见 |
| 离线页面与歌词 | [diskcache](../internal/diskcache)、[lyrics/cache.go](../internal/lyrics/cache.go) | scope/epoch 隔离，旧写入不能复活已失效条目 |
| 字幕与覆盖时间段 | [captionstore/transcript.go](../internal/captionstore/transcript.go) | 读取能看到最新已接受待写入内容；写盘只处理不可变数据 |

新增字段须说明缺失、未知值、非法值及旧版本文件的处理。未知字段的容忍不能演变为允许配置覆盖内部路径、执行命令或注入任意资源。

`preferences.SaveSoon` 先序列化快照，再把字节交给后台保存器。退出或事务提交使用已有 Flush/Wait 保证最新值写完。`userdata.Write` 使用同目录暂存、同步和替换；另一个 `WriteJSON` 接口要求调用方串行写入，不能假定所有辅助方法都提供同等并发或持久性保证。

### 应用数据目录

[mygo.json](../mygo.json) 的应用名为 `Nyago Music`，MyGo 的 `PathUserData`、`PathCache` 和 `PathLogs` 按应用名生成路径。开发构建追加 ` Dev`，与正式构建隔离；不另设第二套路径解析器。

| 平台 | 数据 | 默认缓存 |
| --- | --- | --- |
| macOS | `~/Library/Application Support/Nyago Music` | `~/Library/Caches/Nyago Music` |
| Windows | `%AppData%/Nyago Music` | `%LocalAppData%/Nyago Music` |
| Linux | `${XDG_CONFIG_HOME:-~/.config}/Nyago Music` | `${XDG_CACHE_HOME:-~/.cache}/Nyago Music` |

设置、播放会话、本地曲库索引、离线账号和字幕模型位于数据根目录；歌曲、页面、封面和字幕缓存默认位于缓存根目录。macOS 日志位于 `~/Library/Logs/Nyago Music`，其他桌面平台位于数据目录的 `logs`。下载歌曲默认在 `~/Music/Nyago Music`，属于用户文件，不是缓存。

这次名称切换不执行迁移：不探测或读取 `MyGo 云音乐`、`MyGo 云音乐 Dev`、`Mygo Music` 等旧目录，不复制旧设置中的自选路径，不删除旧文件。新目录中已经保存的设置、曲库和自选缓存/下载路径仍正常恢复。系统凭据不属于目录迁移，当前应用标识未变，钥匙串登录可能沿用；不将其列入 Homebrew 清理规则。

Homebrew 普通卸载只移除应用，显式 `--zap` 只清理正式版的三个 Nyago Music 专用数据、缓存、日志目录。禁止添加旧名称、共享 bundle identifier 对应的系统文件、开发目录、用户下载歌曲或任意自选目录的通配清理。`v0.3.0` 及更早版本仍使用旧路径；新目录规则适用于 `v0.3.1` 起的正式包。

## 7. 乐观编辑与快照

喜欢、收藏、歌单编辑可以先反映到界面，再等待网络结果。回滚必须识别自己仍拥有的编辑，不覆盖后续操作。同一集合有重叠编辑时，只在全部相关编辑稳定后构造最终快照。

[Library.TakeSnapshots](../internal/viewmodel/library/snapshots.go)复制待保存数据；[App playlist_cache](../internal/app/playlist_cache.go)负责账号、epoch、写入预约与读取等待。不可把纯快照构造变成访问 App 的异步任务，也不能在工作线程读取仍在编辑的集合。

## 8. 迁移与文件发布

缓存迁移步骤由现有服务管理：校验路径 → 冻结相关写入 → 暂存复制 → 记录和校验发布 → 提交设置并重绑读取者 → 清理源。只读快照可以按现有事务约定保持打开。失败或取消走回滚，进程中断走日志恢复。

只处理受管理的 `songs`、`browse-v1` 和 `artwork-v2` 等当前布局成员，不能递归移动或删除用户选择目录中的所有文件。解析符号链接和目录等价，拒绝相同、包含或冲突的路径。目录选择和是否迁移由界面决定，文件事务归 `cachemove`。

歌曲导出先在独立暂存副本中写标签并验证，再无覆盖地发布。缓存不完整、质量不匹配或缺少有效元数据时不能充当已完成导出源。详见[下载与缓存](features/download-cache.md)。

## 9. 关闭顺序和资源移交

App 关闭必须协调取消生产者、完成最终保存、释放原生订阅/窗口与停止分发。参考 [shutdown.go](../internal/app/shutdown.go)，不要新增另一个不受它管理的退出路径。

新增资源应回答：谁创建、何时移交、未移交谁关闭、关闭能否重复、投递被丢弃时谁释放、部分启动失败时谁收尾。解码器、文件、图片、订阅、定时器和原生库都适用。

退出不能在 UI 线程阻塞等待一个需要 UI 发布才能结束的工作。下载取消后清理完成的发布有独立状态；模型移除需等待识别器停止；全局快捷键注销后还可能收到旧 portal 结果。

## 10. 最小回归矩阵

每类新异步操作按适用性覆盖：成功、失败、取消、重复输入、乱序返回、同 ID 新请求、账号切换、窗口关闭、退出、磁盘失败、缓存已清除、离线恢复。只读无资源操作不必机械套全部项，但省略必须能由其职责解释。
