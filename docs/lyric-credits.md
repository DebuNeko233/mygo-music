# 歌词制作信息识别

`lyrics.BuildDisplay` 为普通歌词和沉浸式歌词生成同一份分类结果。已确认的制作信息保留在歌词页并按角色和署名去重。其余行继续参与高亮、滚动和前奏或间奏判断。

## 分类规则

- 字段匹配统一全半角 ASCII、大小写和空白，显示仍使用原文。
- `credit_roles.go` 集中维护中文、日文和英文的角色别名。冒号后要有署名。支持由已知角色组成的复合职务、同一职务的中英双写，以及 `Mixed by`、`Recorded at` 等明确署名。
- `Music`、演唱、说唱、合唱和念白等字段需要首尾连续署名块的上下文。行须没有真实逐字时间且不重复，通常还要夹在两条不同的明确署名之间。片头最后一条「演唱」若紧接明确署名，且与正文首句相隔至少 4 秒，也可归入制作信息。相邻署名时间差超过 10 秒时中断署名块。
- 带真实逐字时间或重复出现的明确角色行，需要首尾署名块提供额外证据。LRC 中角色和署名一致的信息也可确认逐字源的制作信息。仅由明确署名组成的逐字源遇到有正文的 LRC 时，会保留署名为补充信息并使用 LRC 正文。
- 正文整首选用 LRC 或 YRC，近似匹配用于译文对齐。YRC JSON 注释可以补充已确认的制作信息，未识别的注释留在播放时间轴之外。

## 回归测试

```sh
go test ./internal/lyrics
```

缓存检查需显式指定 `browse-v1` 目录。它只读并校验缓存载荷，无需联网，也不会修改缓存访问时间。

```sh
NM_LYRICS_CACHE='/path/to/browse-v1' go test ./internal/lyrics -run '^TestCreditsCachedLyrics$' -v
```

可选的 `NM_LYRICS_REPORT=/path/to/private-report.json` 输出少量歌词片段供本地人工复核。缓存测试验证分类结果稳定、制作信息无逐字高亮，以及展示和播放时间轴的间奏区间一致。样本计数只反映测试覆盖范围。
